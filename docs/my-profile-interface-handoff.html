FuturePath AI · My Profile 数据接口交接说明

核查日期：2026-10-23｜交接对象：职业匹配模块组员｜内容基于当前代码和隔离 Chromium 浏览器的虚拟资料实测。

本次没有修改应用代码、存储格式、匹配模块或其他组员的功能；没有接入 PDF 解析，没有生成职业推荐。只新增这份交接文档。下列两份 JSON 来自实际填写后点击 Confirm Profile 的成功页，并与同一测试浏览器的 localStorage 逐字段比较一致，不是预期结构的示意拼装。

交接结论：当前完整档案类型是 Profile；职业匹配页面实际只获得 skills: string。当前没有档案 HTTP API。PDF 只有本地基础检查，没有提取文字或生成档案的流程。正常在线确认流程会设置确认标记，但读取旧档案及路由传值没有统一过滤 confirmed_by_user。

一、当前字段契约

类型依据：artifacts/career-pathways/src/lib/profile.ts 中的 Profile、emptyProfile、normalizeProfile() 和 validateProfile()。字段名是固定代码键，不随界面语言切换。除了 education 对象和 confirmed_by_user 布尔值外，其余字段都是字符串；当前没有数组字段。

字段路径实际类型含义缺失值及当前处理
profile_type"fresh_graduate" | "career_switcher"应届毕业生／转行人士；不是目标职业。读取时仅识别 career_switcher，其余缺失或非法值默认 fresh_graduate。
input_method"pdf_upload" | "online_form"资料输入方式。读取时仅识别 pdf_upload，其余默认 online_form。目前真实生成并确认的 UI 路径只有 online_form；枚举包含 PDF 不代表已实现解析。
education对象教育信息容器，含以下四个字符串字段。读取时缺失／无可用属性会生成四个空字符串，不输出 null 或省略对象。
education.schoolstring学校／大学。缺失或非字符串 → ""。在线表单必填，可明确填写“无”等不适用文本。
education.degreestring学历／学位，自由文本，不是枚举。缺失或非字符串 → ""。在线表单必填，允许明确不适用文本。
education.majorstring专业，自由文本。缺失或非字符串 → ""。在线表单必填，允许明确不适用文本。
education.key_coursesstring主要课程，多项课程仍是一段文本。可空；缺失或非字符串 → ""。不会转换为课程数组。
internship_experiencestring实习经历，可含换行。可空；缺失或非字符串 → ""。“无”原样保留。
academic_experiencestring学术项目、研究或论文经历。可空；缺失或非字符串 → ""。
professional_certificatesstring专业证书列表的自由文本，不是证书数组。可空；缺失或非字符串 → ""。None 不会变成 null。
personal_experiencestring社团、志愿活动等个人经历。可空；缺失或非字符串 → ""。
interests_and_hobbiesstring兴趣爱好，自由文本。可空；读取时还兼容旧 interests 字段。新保存格式只用当前键。
employment_experiencestring就业经历；转行人士表单显示此输入项。可空；新建应届毕业生档案为 ""，但键仍存在。读取旧数据时不会自动删掉非空值；UI 要求明确保留为转行人士或确认移除。旧 experience 可在转行类型下作为回退值。
other_experiencestring其他经历备注，兼容早期资料。可空；缺失时兼容旧 experience，最终非字符串 → ""。旧 experience 在转行档案中可能同时出现在此字段和就业经历中，不能直接当作两段独立经历累加。
skillsstringCurrent Skills；当前唯一实际传给匹配页的档案内容。可空；缺失或非字符串 → ""。推荐传递格式为逗号分隔文本，例如 "Research, Writing"；这仍是当前字符串契约，不是数组。
namestring可选称呼，可用化名；不要求真实姓名。可空；缺失或非字符串 → ""。当前不用于职业匹配。
rolestring当前或最近角色，自由文本；不是推荐职业，也不是 profile_type。可空；缺失或非字符串 → ""。当前不传给职业匹配页。
backgroundstring职业背景补充文本。可空；缺失或非字符串 → ""。当前不传给职业匹配页。
confirmed_by_userboolean用户已检查并点击确认；不代表学校、证书或经历已获独立核验。仅真正的布尔 true 保持为 true；缺失、字符串 "true" 等均变成 false。正常确认保存设置 true。

空值、占位文本、数组和兼容规则

  • normalizeProfile(null)、根层数组和非对象输入返回 null；但普通对象（包括空对象）会被补齐为 Profile，所以标准化不等于资料已通过校验或确认。
  • 字符串不统一 trim，不转换大小写，不翻译用户填写内容；前后空格和换行可以原样保存。ReviewRow 对空白字符串显示“Not provided”，这只是显示文案，不是写入 JSON 的值。
  • ""、"无"、"None" 仍是不同字符串。没有统一的 null、缺失状态或“不适用”枚举。
  • School、Degree、Major 校验时先 trim；空白不通过。明确不适用值为 none / 无 / 沒有 / 没有 / tidak ada / tiada，英文忽略大小写；其他文本 trim 后至少两个字符。校验不会把原字符串改写成 trim 后的值。其余文本字段可空。
  • 给 skills、key_courses、证书或经历传入数组时，标准化会把它变成 ""，不会自动 join，也不会输出数组。把 JSON 数组文字粘进输入框则只是普通字符串，不会被 JSON.parse。
  • 旧 interests、experience 是读取兼容键，不是新输出字段。回退采用空值合并：当前字段为 "" 时不会用旧值替代。未知字段不会由 normalizeProfile 保留。
  • 匹配函数接受英文逗号和全角中文逗号，并做 NFKC、trim、大小写归一及有限中马文技能别名转换。没有通用分号／换行分隔、自然语言技能提取、技能等级、年限或自动剔除“无”／None 占位词的机制。
  • persistConfirmedProfile() 只负责 JSON 序列化和存储成功／失败结果，不自行检查字段、教育必填或确认标记。不能把函数名称当成外部输入校验保证。

二、实际数据流及实现边界

在线填写：已实现

ProfilePage（React 局部 form / profileType / step）
  → submitForm(): validateProfile()，confirmed_by_user = false
  → review 预览 / Edit 编辑
  → confirmProfile(): 就业经历冲突检查，confirmed_by_user = true
  → onSave(confirmed)
  → App.tsx / Router 内的 saveProfile()
  → persistConfirmedProfile(localStorage, next)
  → localStorage["career-pathways-profile"] = JSON.stringify(next)
  → 仅存储成功后 setProfile(next)
  → Router 的 profile 状态更新，传出 profile.skills
  → ProfilePage 成功页显示同一份标准 JSON

刷新时：readProfile() → 读取同一 localStorage 键 → JSON.parse → normalizeProfile → 初始化 Router 的 profile: Profile | null。读取失败或无存储时为 null。在线预览检查教育必填；读取存储时不会重新执行 validateProfile。

未确认草稿：已实现，与正式档案分离

ProfilePage 的局部 form 通过 persistProfileDraft() 暂存到 sessionStorage["career-pathways-profile-draft"]；readProfileDraft() 可在同一标签页刷新／跨页后恢复。草稿 form 的 confirmed_by_user 为 false，草稿本身带 version、baseProfile、profileType、step；这些是草稿信封字段，不是正式 Profile 字段。正常未确认编辑不更新 Router 的已保存 profile。成功确认后清除临时草稿；失败留在预览并保留输入。草稿不是永久备份，也不包含 PDF 文件。

PDF 上传：只实现基础检查，没有解析链路

handleFile() 接收浏览器 File，使用 validatePdfMetadata() 检查非空、.pdf 后缀、application/pdf MIME、最大 10 × 1024 × 1024 字节；再读开头 5 字节的 %PDF- 和末尾 1024 字节内的 %%EOF。通过后仅把 File 放入局部 pdf 状态。

点击 Continue / Parse CV 实际只设置 parseNotice 并显示“提取未配置”，不会从文件名生成资料、不会提取正文、不会创建已确认档案，也没有服务端上传。切换到在线填写后，最终 input_method 仍是 online_form。基础标记检查不能证明文档内部结构完整，不能识别扫描版、加密文件或空白页是否含可提取文本；OCR、文字提取和字段提取均未实现。本轮没有调用或新增 PDF 解析器。

三、职业匹配模块的实际读取位置

以下路径均相对于 artifacts/career-pathways/src/。

位置实际职责与范围
lib/profile.ts导出 Profile、normalizeProfile、validateProfile；第二位组员可以复用这些类型和现有函数，但这些不是网络接口。
components/profile-page.tsx

App.tsx

App.tsx

components/career-planning-pages.tsxPersonalisedRoadmapPage、FutureScenarioPage 也只接 profileSkills 字符串。雷达使用 dataset；SDG 页使用 occupation selection，不读取完整教育／经历档案。

当前真实的路由桥接代码是：

<RolesPage
  dataset={dataset}
  profileSkills={profile?.skills ?? ''}
  onChooseOccupation={chooseOccupation}
/>

当前已接通的字段：仅 skills。当前存在但没有传给匹配页的字段：profile_type、input_method、全部 education、全部经历、证书、兴趣、name、role、background、confirmed_by_user。可从父组件完整状态获得它们，但需要双方确认后扩展 prop，不能把“数据已存储”说成“匹配已使用”。

没有：getConfirmedProfile()、/api/profile、/api/match 这类现成档案接口。检查到 API Server 的当前路由为健康检查；My Profile 并未调用它来存储档案。localStorage 仅同源浏览器可读，不是跨应用、跨设备或给另一位组员机器自动共享的接口。手工改 localStorage 也不会立即触发当前 Router 的 setProfile；正常保存回调会触发状态更新，刷新会重新读取。

确认标记缺口：正常 UI 未确认草稿不会传入匹配。但旧存储可以含 confirmed_by_user=false，readProfile 仍将其加载为 profile，而 /roles、/roadmap、/scenarios 传技能时没有确认标记判断。因此目前不能承诺“所有模块只消费已确认档案”。本轮实测旧档案可被加载并显示需复核提示，未打开匹配页生成结果；无过滤这一结论依据上述实际路由代码。未修复，待双方确认。

六、需要两位组员确认的接口问题（未实施变更）

  1. 交接范围：继续传 skills 字符串，还是由 Router 向职业匹配组件新增完整 Profile prop？当前只有前者，不能假设教育或经历已接通。
  2. 确认门槛：是否统一要求 confirmed_by_user===true 才参与匹配？旧未确认档案是否先引导复核？当前不能保证此门槛。
  3. 空值语义：是否把“无”／None／空白统一视为缺失或不适用？建议同时保留原始文本，不擅自改写用户资料；当前没有统一转换。
  4. 技能格式：短期若保持现状，使用逗号分隔 string，空技能用 ""，不要传数组。若以后采用 string[]，需同步修改类型、标准化、存储迁移和全部消费组件，不能只改匹配函数。还需约定是否处理分号、换行、占位词及未知技能。
  5. 就业经历边界：UI 已明确处理身份切换，但 normalizeProfile 本身不会清除旧应届档案中的就业文本；是否在新接入模块前加一致性验证，需要双方确认。旧 experience 回退可能重复，不可直接重复计权。
  6. 接口版本及 PDF 来源：正式 Profile 没有 schema_version、档案 ID、更新时间、字段来源或技能熟练度。草稿 version=1 不能当作正式接口版本。后续若加入这些字段或 PDF 解析，需要单独约定，当前没有。
  7. 共享与隐私：跨项目或跨设备不能依赖本地存储。是否只做同一 React 应用的 props 集成、显式文件导入导出或以后新增接口，要另行决定；不得默认为上传整份个人资料。当前没有实施这些新能力。

本说明是当前实现的交接快照，不是未来功能承诺。发现的问题仅报告，未擅自修复或改动其他组员模块。
